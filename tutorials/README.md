## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 4 modules (`pipeline.py`, `sample_data.py`, `metrics.py`, `samples.py`) verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 3-file snapshot manifest inline and asserts it against the module's own identity constants before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the revision, the module SHA-256 digests, and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry; `BioClip2Pipeline.from_pretrained(weights_dir=...)` then asserts the pinned config against the package constants, builds `open_clip.model.CLIP` from that config (not from the registry) and loads the safetensors with `strict=True`. The `open_clip_pytorch_model.bin` pickle is not in the manifest and is never loaded (MOD9); no remote code is executed. The notebook never imports `open_clip`, `huggingface_hub` or `safetensors` for model work outside the carried module cells.
- **Runtime (RUN2):** Section 1 installs `open_clip_torch==3.3.0` and its pinned dependencies rather than `transformers`; the runtime cell prints `torch`, `open_clip` and `safetensors` versions.
- **Sample data (DAT1–DAT9):** the 48 photographs are literals in the carried `sample_data` module — CC0 1.0 per photo, one per observer within a species, 224×224, provenance per image, no location — so the default path downloads nothing but the weights. The dataset manifest reports sizes, class counts, ceilings and a digest, and the contact sheet is written to `outputs/bioclip2_biodiversity_contact_sheet.png`.
- **Stages (§4.1):** `generate_sample_dataset` / `load_byod_dataset` (sample acquisition) → `validate_dataset` (validation, with the ceilings and a dataset digest) → `split_dataset` (stratified train/validation/test) → `validate_inputs` with rejection probes → `pipe.embed_images` (representations, with a same-batch identity assertion and a cross-batch tolerance) → `pipe.zero_shot_evaluate` (the model's own prior; plus common-name, open-set, blank and noise probes) → `majority_baseline` + `color_baseline` (fitted on the training split only) → `pipe.adapt` (bounded gradient fine-tuning, head initialised from zero-shot, real on the default path, RUN7/FT2) → `pipe.evaluate` (held-out metrics, deltas against zero-shot and majority) → `pipe.classify` (held-out images as new inputs) → `pipe.save_artifact` (export + provenance) → `BioClip2Pipeline.from_artifact` (fresh-boundary reload and parity assertion).
- **Score semantics (UNC1–UNC4):** zero-shot scores are a softmax over the supplied label set and nothing else — the notebook shows a confident label on a blank image and on noise — and the adapted head's scores are softmax outputs of a head trained on 28 images, **not calibrated probabilities**; the only decision rule is argmax, and deployment thresholding is the caller's. Embeddings are labelled as representations with no intrinsic metric (EVAL9).
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** zero-shot, majority-class and colour baselines are computed on the same test split as the adapted model, and every metric is labelled as tutorial sample-sanity evidence from one seeded holdout with no dispersion estimate. The four species were chosen a priori to be similarly coloured, which is what makes the colour baseline informative; zero-shot is saturated on them, and the notebook says so and says where adaptation earns its keep.
- **Split integrity (SPL1–SPL8):** the split is explicit, stratified and seeded; validation metrics are used for per-epoch monitoring only and the final epoch's weights are kept, so the test split is never used for selection. The notebook states that random splitting assumes independent images and that photographs of one individual, one photographer or one site leak — split by observation, site or photographer on real data.
- **Ceilings (VAL6):** `MAX_IMAGES_PER_CALL = 32`, `MIN_IMAGE_SIDE = 32`, `MAX_IMAGE_SIDE = 8192`, `MAX_LABELS = 64`, the accepted formats, and the record and class minimums and maximums are printed from the schema and the dataset manifest before the model runs; three rejections are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, an uploaded zip is extracted with a path-traversal guard and user data flows through the same validation, split, baselines, adaptation, evaluation, inference, export and reload cells. `BYOD_CLASS_PROMPTS` must map every label to a scientific name. The expected layout and the privacy guidance — location metadata is the sensitive part of a biodiversity record — are stated in the Prerequisites and in Section 4, and the sample dataset is written to `outputs/bioclip2_biodiversity_sample_dataset.csv` with an `images/` folder beside it as a template.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
